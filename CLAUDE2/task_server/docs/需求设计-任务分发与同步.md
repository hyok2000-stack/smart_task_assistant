## 1. 项目背景

### 1.1 现状分析

**Flutter 客户端现状**：
- 单机本地数据存储（SQLite）
- 无法实现多设备间数据同步
- 无法实现用户间任务协作/转发
- 无云端备份能力

**现有后端服务 (task_server) 已实现**：
- ✅ 用户注册/登录（JWT认证）
- ✅ 基础任务CRUD操作
- ✅ 任务转发基础功能
- ✅ PostgreSQL + Redis 架构
- ✅ Docker 部署支持

### 1.2 建设目标

1. **多设备同步**：用户在不同设备上登录后，任务数据实时同步
2. **任务协作**：支持将任务转发给其他用户，实现工作分配
3. **云端备份**：任务数据云端存储，防止数据丢失
4. **离线支持**：支持离线操作，网络恢复后自动同步

```go
// 任务表
type Task struct {
    ID             uint            `gorm:"primarykey"`
    UserID         uint            `gorm:"index;not null"`
    User           User
    TeamID         *uint           `gorm:"index"`
    Team           Team
    Title          string          `gorm:"size:200;not null"`
    Description    string          `gorm:"type:text"`
    Content        string          `gorm:"type:text"` // 原始内容
    Status         int             `gorm:"default:0"` // 0:pending,1:inProgress,2:completed,3:cancelled
    Priority       int             `gorm:"default:1"` // 0:low,1:medium,2:high
    StartTime      *time.Time
    DueTime        *time.Time
    CompletedAt    *time.Time
    Assignee       *uint           `gorm:"index"` // 负责人ID
    ParentTaskID   *uint           `gorm:"index"` // 父任务ID
    IsRecurring    bool            `gorm:"default:false"`
    RecurringRule  string          `gorm:"size:50"` // daily/weekly/monthly
    IsForwarded    bool            `gorm:"default:false"`
    ForwardedBy    *uint           `gorm:"index"`
    ParentRemoteID *uint           `gorm:"index"` // 远程父任务ID（转发时）
    DeviceID       string          `gorm:"size:255;index"` // 创建设备ID
    RemoteID       string          `gorm:"size:255;index"` // 客户端本地ID
    SyncedAt       time.Time       `gorm:"index"` // 最后同步时间
    SyncStatus     string          `gorm:"default:synced"` // synced/conflict/pending
    SyncVersion    int             `gorm:"default:1"` // 乐观锁版本号
    CreatedAt      time.Time
    UpdatedAt      time.Time
    DeletedAt      gorm.DeletedAt `gorm:"index"`

    Tags []Tag `gorm:"many2many:task_tags;"`
}
```

```
│  ┌─────────────────┐    Push              ┌─────────────────┐      │
│  │   服务器       │─────────────────────▶│   客户端 B      │      │
│  │  (合并冲突)     │    实时推送          │  (实时更新)      │      │
│  └─────────────────┘                     └─────────────────┘      │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 5.2 增量同步机制

**客户端拉取（Pull）**：
1. 客户端发送上次同步时间戳 `last_sync_at`
2. 服务器返回该时间之后的所有变更记录
3. 客户端合并变更到本地数据库
4. 客户端更新本地同步时间戳

**客户端推送（Push）**：
1. 客户端检测本地数据变更
2. 记录变更到本地同步队列
3. 网络可用时批量推送到服务器
4. 服务器处理变更并通知其他客户端

### 5.3 冲突解决策略

```
冲突类型                     解决策略
──────────────────────────────────────────────────────
同一任务同时编辑         │  乐观锁 + 时间戳比较（最新时间胜出）
同一任务同时删除         │  删除操作优先
不同设备创建相同远程ID   │  服务器生成新ID，客户端更新
转发任务与原任务冲突     │  原任务状态优先，转发的任务只更新来源
```

**冲突处理流程**：
1. 检测到冲突时，创建 `SyncConflict` 记录
2. 返回冲突信息给客户端
3. 客户端显示冲突，用户选择保留版本
4. 客户端提交选择，服务器更新数据

### 5.4 离线支持

```
离线操作流程：
┌─────────┐   网络断开   ┌──────────┐   网络恢复   ┌─────────┐
│ 客户端  │────────────▶│本地数据库 │────────────▶│ 服务器  │
│ (操作)  │   操作写入  │(队列表)  │  批量同步  │(处理)  │
└─────────┘             └──────────┘             └─────────┘
                              │
                              ▼
                         ┌──────────┐
                         │ UI 显示  │
                         │"待同步" │
                         └──────────┘
```

**离线队列处理**：
1. 所有操作记录到 `OfflineQueue` 表
2. 网络恢复时按时间顺序批量处理
3. 处理失败时标记 `failed`，支持重试
4. 处理成功后删除记录
