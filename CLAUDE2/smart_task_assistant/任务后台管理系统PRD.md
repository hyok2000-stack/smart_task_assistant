# 任务后台管理系统 PRD

| 项目 | 内容 |
|---|---|
| 产品名称 | 智能任务后台管理系统 |
| 适用端 | Flutter APP + 后台管理端 |
| 文档版本 | v1.2 |
| 当前状态 | 评审稿 |
| 文档日期 | 2026-05-16 |

## 1. 背景

当前已有 `smart_task_assistant` APP，具备本地任务管理、提醒、分发等基础能力，但缺少统一账号体系、团队协作、跨设备同步和后台管理能力。

本项目的目标，是在保留 APP 离线可用和本地优先体验的前提下，新增后台管理系统与云端同步能力，让用户可以：

- 在任意一台设备上新增任务
- 登录后将本地任务同步到云端
- 在团队内将任务分发给其他成员
- 接收方自动生成独立任务副本
- 通过后台统一查看用户、团队、设备、同步与分发记录

## 2. 产品目标

### 2.1 业务目标

- 支持个人与团队两种使用方式
- 保留离线模式，提升可用性
- 登录后开启同步，统一管理多设备数据
- 团队成员之间可分发任务，接收方自动生成副本
- 后台可追踪任务流转、评论、同步状态和设备在线状态

### 2.2 体验目标

- APP 保持简单、快速、可离线操作
- 团队内任务分发流程尽量少操作
- 用户不需要接触系统内部 ID
- 同步和分发状态要清晰可见
- 任务评论要像任务本身一样支持离线记录和登录后同步

## 3. 产品原则

1. 本地优先
2. 离线可用
3. 登录后才启用同步
4. 团队内分发
5. 接收方生成任务副本
6. 发送方与接收方任务状态不互相覆盖
7. 双方只同步分发状态
8. 用户不直接看到 userId 或 deviceId
9. 附件一期不做实际上传，仅预留字段和接口
10. 评论属于任务协作内容，登录后参与同步

## 4. 角色定义

### 4.1 普通成员

- 使用 APP 新增、编辑、完成、删除自己的任务
- 离线可用
- 登录后同步本地任务
- 接收团队成员分发的任务
- 查看自己发出的任务分发状态
- 对自己的任务和接收的任务副本发表评论

### 4.2 团队管理员

- 管理团队成员
- 查看团队内所有成员任务
- 查看设备在线状态
- 查看同步日志与分发日志
- 查看团队任务评论记录

### 4.3 系统管理员

- 管理全部用户、团队、设备、日志和系统配置

## 5. 使用边界

### 5.1 一期范围内要做

- 注册、登录、退出
- 团队创建与成员管理
- 设备绑定与在线心跳
- 本地任务离线使用
- 登录后任务同步
- 团队成员间任务分发
- 接收方自动生成任务副本
- 任务评论与评论同步
- 同步日志、分发日志、设备日志
- 后台管理端

### 5.2 一期暂不做

- 附件实际上传、下载、预览
- 复杂权限矩阵
- 即时聊天
- 审批流
- 报表大屏
- 第三方通知通道
- 多团队协作

## 6. 核心业务规则

### 6.1 数据归属

- 任务以“账号”维度归属
- 团队分发任务以“成员”维度投递
- 设备只负责在线投递和回执，不作为业务主对象

### 6.2 身份标识

- 用户选择对象时，通过团队通讯录选人
- 前端展示昵称、头像、在线状态、团队信息
- 系统内部使用 `recipientUserId`
- 用户不需要知道对方 ID

### 6.3 同步规则

- APP 支持离线新增、编辑、完成、删除任务
- 未登录时仅本地保存
- 登录后才开启云同步
- 冲突处理以本地最新版本为准
- 不要求云端强制覆盖本地

### 6.4 分发规则

- 只能向同一团队内成员分发任务
- 分发后生成接收方任务副本
- 副本与原任务互不覆盖
- 双方只同步分发状态
- 分发记录可追踪，支持回执

### 6.5 附件规则

- 一期不开放附件功能
- 任务模型预留附件字段
- 后续可扩展附件上传、下载和预览

### 6.6 评论规则

- 评论归属于具体任务
- 评论只在同一任务实例内跨设备同步
- 用户可对自己拥有的任务发表评论
- 接收方可对分发生成的任务副本发表评论
- 原任务与接收方副本是两条独立评论线程，评论正文不互相同步
- 发送方可通过分发详情查看接收方任务副本的评论数量、最后评论时间和最后一条评论摘要
- 团队管理员可查看团队内任务评论记录
- 评论支持离线创建，登录并联网后同步
- 评论删除采用软删除，保留审计记录

## 7. 功能需求

### 7.1 注册与登录

#### 功能描述

用户可通过手机号或邮箱注册账号，登录后启用同步和团队分发能力。

#### 需求点

- 支持手机号注册、邮箱注册
- 支持密码登录
- 支持退出登录
- 支持找回密码的预留能力
- 登录成功后自动关联当前设备
- 未登录状态仍可使用本地任务功能

#### 验收标准

- 未登录可正常创建本地任务
- 登录后能同步本地任务
- 登录后可进入团队和分发功能

### 7.2 团队管理

#### 功能描述

支持创建团队、邀请成员、查看成员状态和管理团队关系。

#### 需求点

- 创建团队
- 邀请成员加入团队
- 成员状态：待加入、正常、禁用、退出
- 角色：团队管理员、普通成员
- 团队管理员可查看团队内所有成员任务

#### 验收标准

- 成员只能在所属团队内查看和接收任务
- 管理员可查看团队内成员列表和任务概况

### 7.3 设备管理

#### 功能描述

每个登录设备都需要绑定到账号，用于长期在线、同步和接收分发消息。

#### 需求点

- 每台设备生成唯一设备标识
- 支持设备绑定、解绑、重命名
- 支持设备在线状态显示
- 支持最近在线时间、最近同步时间
- 设备长期在线，通过心跳维持状态

#### 验收标准

- 登录后设备能被后台识别
- 设备在线状态可查询

### 7.4 本地任务管理

#### 功能描述

APP 保留本地任务管理能力，保证离线状态下也能使用。

#### 需求点

- 本地新增任务
- 本地编辑任务
- 本地完成任务
- 本地删除任务
- 支持标题、内容、优先级、截止时间、提醒时间、标签等基础字段
- 本地数据优先保存

#### 验收标准

- 断网或未登录时仍能正常操作任务
- APP 重启后本地数据可恢复

### 7.5 云同步

#### 功能描述

登录后，设备将本地任务与云端同步，云端作为多设备数据交换中心。

#### 需求点

- 支持任务新增同步
- 支持任务编辑同步
- 支持任务完成同步
- 支持任务删除同步
- 支持任务评论新增、删除同步
- 支持离线队列，网络恢复后自动补同步
- 记录同步结果和失败原因

#### 冲突规则

- 以本地最新版本为准
- 不自动覆盖用户当前设备上的最新内容

#### 验收标准

- 登录后本地任务能进入云端
- 其他设备能同步到最新状态
- 同步失败可重试并可查询原因

### 7.6 团队任务分发

#### 功能描述

用户可在团队内将任务分发给其他成员。接收方收到后自动生成一张任务卡片。

#### 需求点

- 只能选择同团队成员
- 分发目标通过通讯录选择，不显示 ID
- 分发后生成接收方任务副本
- 副本标记来源为“团队分发”
- 分发记录需可查询
- 接收方任务状态独立于发送方任务

#### 分发状态

- 已发送
- 已接收
- 已生成任务卡片
- 已查看
- 已完成
- 失败

#### 验收标准

- A 分发给 B 后，B 收到独立副本
- B 修改任务不会影响 A 原任务状态
- A 能看到分发状态变化

### 7.7 任务卡片生成规则

#### 功能描述

接收方 APP 自动创建标准任务卡片。

#### 卡片来源信息

- 来源类型：团队分发
- 发送人名称
- 原任务标题
- 原任务内容
- 截止时间
- 优先级
- 分发备注
- 原任务标识
- 分发标识

#### 验收标准

- 接收方打开 APP 后可看到自动生成的任务卡片
- 卡片样式与普通任务一致，但来源清晰可辨

### 7.8 任务评论

#### 功能描述

用户可在任务详情中发表评论，用于记录任务处理过程、补充说明和协作反馈。评论支持本地保存，登录后同步到云端。

#### 需求点

- 支持新增文字评论
- 支持删除自己的评论
- 支持查看评论列表
- 支持评论创建时间、评论人、来源设备展示
- 支持离线评论，联网后自动同步
- 支持后台查看评论记录
- 评论内容一期仅支持文本

#### 可见性规则

- 普通成员可查看自己任务下的评论
- 接收方可查看自己任务副本下的评论
- 发送方可在分发详情中查看接收方副本评论摘要
- 团队管理员可查看团队内任务评论
- 非团队成员不可查看评论

#### 同步规则

- 评论以 `commentId` 作为唯一标识
- 离线创建评论时，客户端必须生成 `clientCommentId`，用于同步重试去重
- 每次评论新增、删除操作必须生成 `operationId`，服务端按 `operationId` 保证幂等
- 云端保存 `serverCreatedAt`，评论最终展示顺序以 `serverCreatedAt` 为准
- 未同步评论可先按本地创建时间展示，云端确认后再校准顺序
- 评论新增、删除进入同步队列
- 同一评论不做编辑，一期如需修改，采用删除后重新评论
- 评论按 `serverCreatedAt` 正序展示
- 评论删除后本地和云端均标记为已删除

#### 验收标准

- 未登录时可对本地任务发表评论
- 登录后本地评论可同步到云端
- 多设备登录后可看到同一任务的评论
- 接收方副本评论不覆盖发送方原任务评论
- 团队管理员可在后台查看评论记录

### 7.9 后台管理端

#### 功能描述

后台用于统一管理用户、团队、设备、任务、日志和系统配置。

#### 页面范围

- 登录页
- 仪表盘
- 用户管理
- 团队管理
- 成员管理
- 设备管理
- 任务管理
- 评论管理
- 同步日志
- 分发日志
- 异常日志
- 系统配置

#### 仪表盘指标

- 今日新增任务数
- 待同步任务数
- 分发成功数
- 分发失败数
- 今日新增评论数
- 在线设备数
- 团队成员数

## 11. 关键流程

### 11.1 未登录新增任务

1. 用户打开 APP
2. 新建任务
3. 任务保存在本地
4. 不触发云同步

### 11.2 登录后同步本地任务

1. 用户登录
2. 当前设备绑定账号
3. 本地任务进入同步队列
4. 云端接收并分发到其他设备

### 11.3 团队内分发任务

1. 用户选择任务
2. 在团队成员中选择接收人
3. 系统创建分发记录
4. 接收方生成任务副本
5. 双方仅同步分发状态

### 11.4 评论同步

1. 用户在任务详情中发表评论
2. APP 先保存到本地评论表
3. APP 生成 `clientCommentId` 和 `operationId`
4. 已登录且联网时，评论进入云端同步
5. 服务端按 `operationId` 幂等处理，避免重复评论
6. 其他设备拉取同一任务实例的评论变更
7. 评论按 `serverCreatedAt` 展示
8. 删除评论时同步删除标记

## 12. 验收标准

- 未登录可离线新增任务
- 登录后可同步本地任务
- 团队成员只能看到分发给自己的任务
- 团队管理员可查看团队内所有成员任务
- 分发后生成接收方任务副本
- 发起方与接收方任务状态不互相覆盖
- 任务评论可离线创建并在登录后同步
- 接收方副本评论不覆盖发送方原任务评论
- 原任务与接收方副本的评论正文不互相同步
- 离线评论重复同步不会生成重复评论
- 团队管理员可查看团队内任务评论
- 用户不需要知道对方 ID
- 附件功能未上线，但字段与接口已预留

## 13. 风险与待确认项

### 13.1 风险

- 多设备长期在线的心跳成本较高
- 离线修改与云端同步的冲突需要严格定义版本规则
- 团队分发副本的撤回与删除需要后续补充边界
- 评论离线同步需要避免重复提交和顺序错乱

### 13.2 待确认

- 设备在线心跳间隔
- 同步轮询或推送方式
- 任务撤回规则
- 是否支持同一用户多设备同时在线接收
- 评论是否需要支持编辑、@成员、图片或语音

## 14. 结论

本项目采用“本地优先 + 登录同步 + 团队内分发”的模式，既保留现有 APP 的离线体验，也补足团队协作与后台管控能力。  
当前版本可直接进入原型设计、接口设计和开发拆分阶段。
